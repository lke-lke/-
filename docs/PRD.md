# 筝一小助理作业管理平台：台账全链路打通 PRD

> 文档状态：待业务确认  
> 规格版本：V1.0  
> 更新日期：2026-09-05  
> 本轮性质：Full（跨台账、组织、任务、审核、数据库、看板，并修改数据库契约）  
> 权威边界：本文是本轮产品与业务口径的唯一来源；技术实现以 `docs/ARCHITECTURE.md` 为准，开发状态只在 `docs/TASKS.md` 维护。

## 1. 背景与目标

当前平台已具备任务、人员、交付物、双层审核、返修、结项与看板的 Demo 能力，但 Excel 台账导入仍是孤立入口：导入时需要人工为整批数据指定小组和负责人，任务挂链未自动匹配，参与人未写入规范化关系，导入结果也未完整驱动各角色页面与待办。

本轮目标是让一份任务台账从上传开始，自动完成字段标准化、三级任务挂链、人员识别、组别归属、任务创建或更新、待办生成与看板统计，并与组员交付、组长审核、管理员二级审核、返修和结项形成闭环。未来 1d/智能调度系统通过同一标准入库契约写入，不另建第二条业务链路。

## 2. 成功标准

1. 上传一份合法任务台账后，每一有效行都得到可追溯的处理结果：已创建、已更新、待完善、冲突或失败。
2. 可识别的“对应验收同学”自动匹配真实成员和小组，生成任务参与关系；不得再要求整批指定同一个小组和负责人。
3. 可识别的任务归属、主任务和任务分组自动挂载到有效任务关系；匹配失败不得静默归入“临时任务”。
4. 新任务立即出现在管理员任务全景、对应组长本组任务、对应组员我的任务及相关看板中。
5. 组员上传交付物后，组长可选择“验收并结束”或“提交管理员二级验收”；所有驳回和返修均可闭环并留痕。
6. 任务只有在必要交付物、返修、人员标签、最终难度和结项信息全部满足时才进入“已完成”。
7. 重复导入不会重复建单，且不会覆盖组长已经手工确认的字段。
8. 本地 Supabase 可完整重建和验证；迁移与接口可被 1d 的 Supabase 兼容数据库顺序复用。

## 3. 范围

### 3.1 本轮范围

- Excel 任务台账解析、预览、校验、异常处理、提交和重试。
- 组长手工创建完整任务，并与导入任务复用相同的人员、关系和状态校验。
- 调整后的核心字段映射。
- 筝一 B/C/D 三组成员与人员别名识别。
- 任务归属、主任务、任务分组、任务名称四级展示关系的自动挂链。
- 任务、任务参与人、导入来源、字段锁和待办的规范化落库。
- 管理员、组长、组员及超级管理员的任务可见性和操作链路。
- 交付物单级/二级审核、驳回、返修、重新提交、结项闭环。
- 各组作业总览、任务全景、本组任务、人员作业明细和审核中心的数据同步。
- 对未来 1d/智能调度系统预留统一标准入库接口。

### 3.2 非本轮范围

- 真实标注平台 API 的定时进度同步；本轮只固化接口与快照规则。
- 真实钉钉消息发送；本轮生成站内待办和通知事件，并保留通知适配器。
- 直接连接公司内网 1d 环境或代替内网团队执行部署。
- 自动从自由文本推断任务难度或个人主观贡献分。

## 4. 角色与权限

### 4.1 角色

| 角色 | 数据范围 | 核心权限 |
|---|---|---|
| 超级管理员 | 全部 | 联调期全功能；可只读预览管理员/组长/组员视角；正式上线后可配置停用 |
| 管理员 | 全部小组 | 导入台账、查看和管理全局任务、审核组长提交的二级验收交付物、查看审计与异常 |
| 组长 | 本组 | 手工建任务、完善导入任务、维护本组人员与任务关系、分配负责人、审核交付物、决定审核路线、结项 |
| 组员 | 本人参与任务 | 查看本人任务，上传/更新本人交付物，挂载或移除本人未确认工作标签，按意见返修 |

### 4.2 身份原则

- 页面可以按“管理员、组长、组员”呈现角色入口，但后台所有写操作必须记录真实 `user_id`。
- 本地无密码模式只用于联调，使用独立的本地演示身份，不得进入正式数据库。
- 正式 1d 环境通过钉钉/OneDay Auth 绑定真实用户、角色和小组，前端不得自行提交角色来提升权限。
- 历史审计保留操作者当时的姓名、角色和小组快照，不因后续调组或改名被改写。

## 5. 权威业务数据模型

### 5.1 任务层级

任务页面统一使用以下字段和顺序：

`任务归属 → 主任务 → 任务分组 → 任务名称`

- “任务归属”是最高业务项目，如 `AI试穿-模型评测`、`lookie横向评测`。
- “主任务”是归属下的一级任务主题。
- “任务分组”是主任务下的标准子任务类别。
- “任务名称”是台账中一次具体作业任务的名称，不作为关系库的替代品。
- “临时任务”表示业务上明确没有主任务从属关系的任务；它不是匹配失败的兜底桶。

## 6. 调整后的任务台账字段映射

### 6.1 正式映射

| Excel 字段 | 系统字段 | 处理规则 |
|---|---|---|
| 任务名称 | 任务名称 | 必填；保留原文并生成标准化检索值 |
| 任务id | 外部任务 ID / 平台任务 ID | 优先作为幂等键；按字符串读取，禁止科学计数法和前导零丢失 |
| 任务归属 | 任务归属 | 标准化后参与任务关系匹配 |
| 任务分组 | 任务分组 | 先与任务关系库匹配，再反查主任务；不得直接写死主任务 |
| 作业性质 | 作业性质 | 标准化为首次交付、回扫、补标或待完善 |
| 数据量级 | 数据量 | 支持纯数字、千分位、k/w/万等单位转换；原值留档 |
| 作业人力 | 作业人力 | 支持整数或可解释数值；异常值进入待完善 |
| 任务下发时间 | 业务下发时间 | 不得覆盖系统创建时间 |
| 预期交付时间 | 预计截止时间 | 组长可修改，修改后加人工锁并留痕 |
| 对应验收同学 | 参与人来源 / 自动归组来源 | 拆分姓名、解析别名、匹配人员和小组，生成任务参与关系 |
| 规则文档 | 任务已有资料 / 来源文档链接 | 保留台账已有资料入口；仅作来源资料，不视为平台已上传、已验收交付物 |

### 6.2 明确不进入任务业务字段的列

以下两列仅保留在导入原始行和审计记录中，不写入正式任务字段、不生成参与关系、不出现在正式任务页面：

- 对应任务组长（站点）
- 数据报告同学

新代码必须停止从前两列生成 `team_leader`、`data_reporter` 等业务值。台账“规则文档”只进入 `rule_doc_link` 作为已有资料入口，不生成审核通过记录，也不参与交付物齐套判断。既有废弃数据库列暂不在同一迁移中物理删除，先停止读写并完成历史兼容审计；是否最终删除由独立迁移决定。

### 6.3 原始数据保留

- 每个导入批次保存文件名、文件校验值、操作者、上传时间、工作表和总行数。
- 每一行保留原始字段 JSON、标准化结果、匹配结果、错误信息和最终关联任务。
- 原始行只用于审计和问题排查，不作为看板统计源。
- 原始文件和导入记录的保留周期由部署环境配置；默认保留 365 天，涉及已创建任务的行级审计长期保留。

## 7. Excel 解析与标准化

### 7.1 文件识别

- 任务台账通过工作表名、必填表头和版本规则识别，不能只依赖一个固定 Sheet 名。
- 表头支持换行、前后空格和常见全半角差异。
- 合并单元格产生的空值，只允许对明确声明可向下填充的分类列继承；任务名称、任务 ID、人员和日期不得盲目继承。

### 7.2 数据格式

- 任务 ID 始终按文本读取；若 Excel 已把长 ID 转为科学计数法且无法无损恢复，则标记为异常，不猜测。
- 姓名分隔符支持顿号、中文/英文逗号、斜杠、分号、空白和换行。
- 日期支持 Excel serial、`YYYY-MM-DD`、`YYYY/MM/DD` 和带时间格式，统一转换为 Asia/Shanghai。
- 数据量支持整数、小数、千分位和 `k/K/w/W/万`；无法确定的文本不转换为 0，而是进入待完善。
- `/`、`-`、空字符串只在字段规则明确允许时视为空值。

## 8. 人员识别与自动归组

### 8.1 匹配顺序

1. 规范化原始姓名：去空格、统一标点、拆分多人。
2. 先匹配有效人员标准姓名。
3. 再匹配有效人员别名。
4. 获取人员在业务下发日期时有效的小组关系；无业务日期时使用当前有效关系。
5. 汇总匹配结果并决定是否自动归组。

### 8.2 决策规则

| 场景 | 系统处理 |
|---|---|
| 所有人均匹配且属于同一组 | 自动写入小组、组长和所有参与人 |
| 只有一名普通组员 | 自动设为主负责人 |
| 多名普通组员 | 全部设为参与人；主负责人留空并生成组长待办 |
| 只有组长 | 自动归组；主负责人待组长分配 |
| 含未知姓名 | 行进入待完善，已识别结果可保留但不得自动提交为完整任务 |
| 匹配到多个同名人员 | 行进入冲突，必须人工选择具体用户 |
| 人员跨多个小组 | 行进入冲突，不自动选择小组 |
| 人员已停用但下发日存在历史有效组别 | 允许建立历史参与关系并提示确认 |

组长人工修正匹配后，该行可重新提交。人工修正只影响当前任务，不自动修改全局人员别名；如需长期复用，由组长在人员管理中新增别名。

## 9. 任务关系匹配

### 9.1 匹配顺序

1. 使用标准化后的“任务归属＋任务分组”匹配有效关系。
2. 使用任务关系别名匹配。
3. 若任务分组在某任务归属下只对应一个有效主任务，可唯一反推主任务。
4. 若台账明确填写“临时任务”或 `/`，按临时任务规则处理。
5. 其余情况进入待完善或冲突队列，不自动创建新关系。

### 9.2 动态关系管理

- 组长可新增、修改、停用任务关系和别名；只能管理本业务允许的关系范围。
- 自定义值仅用于当前任务时，可以作为任务快照保存，但必须标记 `custom`。
- 需要长期复用时，组长将其正式加入任务关系库。
- 停用关系不影响历史任务快照；新导入不得再自动匹配到已停用关系。
- 当前基线继续要求 AI 试穿 66 项、lookie 10 项关系完整，但后续数量允许通过正式变更增长。

## 10. 导入预览与提交

### 10.1 预览页面

预览必须显示：

- 批次摘要：文件、总行数、可直接提交、待完善、冲突、失败。
- 每行核心字段及人员、小组、主任务和任务分组匹配结果。
- 警告和错误原因，支持按状态筛选。
- 新建任务/更新已有任务的判断。
- 台账值与系统值的差异。
- 可导出错误明细。

取消“为整批任务指定同一个小组和负责人”的现有交互。管理员可提交所有有效行，也可只提交选中行；异常行保留在批次中等待修正。

### 10.2 行级结果

| 状态 | 含义 |
|---|---|
| ready | 校验和匹配均通过，可提交 |
| needs_completion | 缺少可由组长补充的非阻断字段 |
| conflict | 人员、关系或已有任务存在冲突，提交前必须处理 |
| error | 缺少任务名称等不可创建条件，或数据无法解析 |
| created | 已创建任务 |
| updated | 已更新已有任务的可更新字段 |
| skipped | 用户未选择或该行无需变更 |

批次允许部分成功。提交必须由数据库 RPC 在行级事务中完成，单行失败不回滚其他成功行；批次最终状态为成功、部分成功或失败。

## 11. 幂等、更新与人工字段保护

### 11.1 幂等键

1. 有外部任务 ID：`source_system + external_task_id`。
2. 无外部任务 ID：`source_system + 标准化任务名称 + 业务下发日期` 的稳定哈希。
3. 两种键均缺少必要输入时，不自动提交。

### 11.2 重复导入

- 重复键命中已有任务时默认进入“更新预览”，不创建第二条任务。
- 完全相同的输入标记为 skipped。
- 更新后保留每一次导入批次和字段差异。

### 11.3 字段来源和人工锁

- 每个可导入字段记录最近来源：excel、scheduler、manual。
- 组长或管理员手工确认后，该字段进入人工锁状态。
- 后续 Excel 或调度数据不得静默覆盖人工锁字段，只生成冲突供人工选择。
- 文档、审核、返修、工作标签、最终难度、结项和审计永远不能被外部数据源覆盖。

## 12. 组长手工创建任务

- 组长可绕过 Excel，在本组任务管理页面手工填写同一套核心任务字段。
- 任务归属、主任务和任务分组使用相同关系解析服务，支持标准下拉和当前任务自定义快照。
- 参与人从本组有效成员中多选；一个普通组员时可自动成为主负责人，多人时由组长明确指定主负责人。
- 新建时必填任务名称、任务归属/临时任务声明、任务分组、小组、主负责人、业务下发时间、预计截止时间和初始难度。
- 实际截止时间在任务结项时填写，创建阶段不要求也不允许伪造未来实际时间。
- 手工创建字段从一开始标记为 manual 且人工锁定，后续 Excel/调度数据不得静默覆盖。
- 如果后来导入同一个外部任务 ID，系统应关联现有任务并进入差异确认，不创建重复任务。

## 13. 任务创建与状态机

### 13.1 内部状态

本轮统一内部任务状态：

`待完善 → 待开始 → 进行中 → 待确认 → 已完成`

- 待完善：缺少小组、主负责人、有效关系或预计截止时间等必填管理字段。
- 待开始：必填字段完整，尚无实际作业进度或开始动作。
- 进行中：已有开始事件、平台进度大于 0，或组长主动开始。
- 待确认：数据作业已完成，正在等待交付物、审核、贡献标签或结项确认。
- 已完成：结项条件全部满足并由组长确认。

旧值 `数据完成`、`待交付`、`待验收` 在迁移时按明确映射转为 `待确认`；不得再通过标签互换维持双重口径。

### 13.2 合法流转

- 待完善字段补齐后进入待开始。
- 待开始由进度/开始事件进入进行中。
- 进行中在数据完成后进入待确认。
- 待确认完成结项进入已完成。
- 返修不单独改变任务主状态，任务继续保持待确认，并由交付物工作流记录返修阶段。
- 已完成任务只允许通过受控“重新打开”动作回到待确认，并必须填写原因、记录审计。

### 13.3 任务创建结果

- 自动匹配完整：创建为待开始。
- 人员或关系等管理字段缺失：创建为待完善并生成对应组长待办。
- 小组无法确定：任务可作为导入草稿保留，但不进入任何小组正式任务列表和业务看板。

## 14. 三角色全链路

### 14.1 管理员/筝一

1. 上传并预览台账。
2. 处理阻断冲突或提交有效行。
3. 在任务全景和各组作业总览查看任务与人员状态。
4. 接收组长提交的管理员二级审核交付物。
5. 通过后交付物完成；驳回后回到对应组长，保留管理员驳回次数。

### 14.2 组长

1. 在“待完善项目”收到新导入任务提醒。
2. 补齐负责人、预计截止时间、任务关系、初始难度等字段。
3. 管理本组人员、任务分配和进行中任务。
4. 审核组员交付物：驳回组员、通过并结束、通过并提交管理员。
5. 处理管理员驳回：自行修改并重提，或退回组员上传新版本。
6. 在结项时确认最终难度、已验收交付物和客观工作标签。

### 14.3 组员

1. 在“我的任务”看到本人参与任务。
2. 上传本人交付物和返修版本。
3. 挂载系统提供的工作标签；说明和关联证据选填。
4. 只能增删改本人尚未被确认、且任务尚未结项的产出和标签。
5. 收到组长驳回后按意见提交新版本，历史版本不可覆盖。

## 15. 交付物审核与返修

### 15.1 路线选择

- 每份交付物首次提交时路线为 undecided。
- 组长审核时动态选择：leader_only 或 leader_then_admin。
- 一旦进入 leader_then_admin，后续版本不得降级为 leader_only。

### 15.2 单级路线

`组员提交 → 组长通过 → 交付物完成`

组长驳回时：`组员提交 → 组长驳回 → 组员新版本 → 组长复核`。

### 15.3 二级路线

`组员提交 → 组长通过并提交管理员 → 管理员通过 → 交付物完成`

管理员驳回后：

- 组长修改并重新提交管理员；或
- 组长退回组员，组员上传新版本，重新经过组长，再提交管理员。

每次动作记录根交付物、版本、操作者、角色、前后状态、意见和时间；组长驳回次数与管理员驳回次数分别累计。

## 16. 客观工作标签与结项

系统标签基线：规则文档撰写、需求文档撰写、需求文档培训、规则培训、过程答疑、作业中规则变更并下发、回扫安排/发起、数据验收、数据分析、评测报告撰写、其他已验收交付物、组员带教。

- 文档类标签优先关联已验收交付物。
- 回扫和验收类标签可关联现有记录。
- 培训、答疑、规则变更、带教等说明和证据为选填。
- 不采用主观贡献比例或主观打分。
- 标签由成员本人或组长挂载，只有组长确认后才计入工作量。
- 同一任务的最终难度点数按每人已确认客观标签数占该任务全部已确认标签数的比例分配；不提供人工贡献比例输入框。

任务结项必须同时满足：

1. 任务处于待确认。
2. 必要交付物均已完成其审核路线。
3. 不存在待处理组员返修、组长返修或管理员审核。
4. 参与人和客观工作标签已确认。
5. 最终难度 1–5 星已确认并留痕。
6. 实际截止时间已写入。
7. 组长提交结项摘要。

## 17. 回扫记录兼容与关联

- 现有业务借调/回扫台账继续作为任务过程事件来源，本轮改造不得破坏已有回扫登记页面和记录。
- 回扫优先通过外部任务 ID 关联；无 ID 时按标准化任务名称、对接业务助理、日期和候选小组生成匹配队列，不直接猜测唯一任务。
- 自动唯一匹配可进入待确认；无匹配或多候选由对应组长确认原任务。
- 回扫量、执行人、原因、开始/完成时间和验收结果写入规范化回扫记录，原始台账行继续留档。
- 回扫过程不作为任务独立主状态；未完成/未验收回扫会阻止任务结项，并在任务待确认和组长待办中体现。
- 已验收回扫可以作为“回扫安排/发起”工作标签的客观关联证据。

## 18. 待办与通知

统一待办事件包括：

- imported_task_needs_completion：导入任务待完善。
- task_needs_assignee：多人任务待指定主负责人。
- member_added_to_task：成员被加入任务。
- deliverable_pending_leader_review：交付物待组长审核。
- deliverable_member_revision：交付物待组员返修。
- deliverable_pending_admin_review：交付物待管理员审核。
- deliverable_leader_revision：管理员驳回待组长处理。
- task_ready_for_settlement：任务满足结项前置条件。
- import_conflict：导入冲突待处理。

站内待办是权威事实；钉钉消息是可选投递渠道。待办按事件生成并可标记已处理，不依赖前端临时计算。

## 19. 看板与时间统计口径

### 19.1 全局时间筛选

各组作业总览支持日、周、月、季度、自定义区间；同一筛选影响页面全部模块。

### 19.2 统计规则

- 状态分布：使用筛选区间结束时的任务状态快照。
- 新增任务：按业务下发时间；缺失时按系统创建时间并标注来源。
- 已完成任务：按任务结项时间。
- 当周完成工作量：按任务结项时间计入，主排名指标保持不变。
- 交付物产出：按最终审核通过时间。
- 人员贡献：按任务结项时确认的标签和最终难度计入。
- 回扫支持时长：按已关联任务的回扫记录 `support_hours` 汇总，作为过程工时事实展示，不额外改变任务难度点数。
- 进行中任务的数据量和平台进度必须按任务 ID 分开展示，不跨任务合计成一行。
- 难度分布只显示数量大于 0 的星级。

### 19.3 组织历史

按任务的归属小组快照统计历史数据，不因成员后续调组重算旧任务。管理者可另行查看“按当前组织”的人员列表，但不得与历史任务归属混用。

## 20. 文件存储规则

- 文件存入私有对象存储，数据库只保存元数据、对象键、校验值和版本关系。
- 前端通过服务端签发的上传意图直传，不接触服务端密钥。
- 上传登记必须绑定真实用户；前端传入的 uploader 仅可作为展示建议，不能作为权限事实。
- 已审核、被标签引用或已结项任务下的文件不可物理删除，只允许作废并留痕。
- 新版本新增记录并关联根交付物，不覆盖旧文件。
- 1d 迁移通过对象键/映射表转换地址，业务记录不保存短期预签名 URL。

## 21. 未来 1d/智能调度接入

- Excel 和调度系统都调用同一个标准化任务入库服务。
- 调度系统使用 `source_system + external_task_id` 和 Idempotency-Key 幂等。
- 外部系统可更新未被人工锁定的任务基础字段和进度快照。
- 外部系统不得覆盖文档、审核、返修、贡献、最终难度、结项和审计。
- 接口必须有版本号、请求 ID、来源时间、来源版本和签名/服务身份。
- 同步运行记录接收数、应用数、跳过数、冲突数、错误数和游标。

## 22. 非功能要求

- 单次导入建议上限 5,000 行；超过上限应分批并提示。
- 预览和提交不得阻塞浏览器主线程；大批次在后端处理并可查询进度。
- 列表必须分页，任务和人员筛选字段建立索引。
- 所有写 RPC 必须校验身份、角色、任务所属组和当前状态。
- 错误返回稳定错误码，不把数据库内部信息直接暴露给前端。
- 关键动作必须写审计：导入、人工覆盖、关系变更、人员别名变更、状态流转、审核、返修、结项和重新打开。

## 23. 迁移与上线要求

- `supabase/migrations/` 是唯一可执行数据库来源，已共享 migration 不回改。
- 开发顺序：本地新迁移 → `db reset` → DB lint/test → 类型生成 → 前端构建 → 全链路验收。
- 上线前备份共享数据库并记录 migration 版本。
- 历史任务状态、业务时间、废弃字段和参与人必须有明确迁移报告。
- 通过兼容迁移和接口版本实现回退；禁止通过删除历史 migration 回滚。

## 24. 验收矩阵

至少覆盖以下场景：

1. 标准任务 ID、长数字 ID、前导零 ID、科学计数法异常。
2. 单人同组、多人同组、只有组长、未知人员、同名人员、跨组人员。
3. `阿部`、`成研`均匹配为 C 组成妍。
4. 精确任务关系、关系别名、唯一反推、明确临时任务、未匹配和多候选冲突。
5. 纯数字、千分位、k/w/万和不可解析数据量。
6. 首次导入、重复无变化、重复有更新、人工锁冲突、部分成功和失败行重试。
7. 自动任务在管理员、对应组长和对应组员页面可见。
8. 待完善任务生成组长待办，补齐后进入待开始。
9. 单级交付物审核、组长驳回、多版本返修。
10. 二级审核、管理员驳回、组长直接重提、退回组员后重提、多轮返修计数。
11. 不满足结项条件时禁止完成，满足后结项并同步全部看板。
12. 日/周/月/季度/自定义时间筛选口径一致。
13. 管理员、组长、组员和超级管理员的 RLS 越权测试。
14. 本地无密码模式和正式认证模式数据边界测试。
15. 1d 标准入库接口与 Excel 导入产生相同规范化结果。
16. 组长手工创建任务与台账创建任务遵守相同关系、人员、权限和状态规则。
17. 回扫台账可唯一匹配、人工确认、阻止未完成任务结项，并可作为工作标签证据。

## 25. 业务默认决策

为避免实现期间反复猜测，本规格采用以下默认：

- 多名普通组员同组时不自动选择主负责人，由组长确认。
- 人员跨组时整行进入冲突，不自动拆成多个任务。
- 匹配失败不自动创建全局人员、别名或任务关系。
- 任务创建后使用任务归属小组快照统计历史。
- 导入批次允许部分成功，错误行可重试。
- 人工确认优先级高于 Excel 和未来调度数据。
- 台账“规则文档”作为任务已有资料链接迁入，但只有平台内上传并完成既定审核路线的交付物才参与齐套、结项和工作量证据判断。

## 26. 完成定义

只有当 `docs/TASKS.md` 中全部 P0/P1 开发任务完成，数据库迁移可从空库顺序执行，自动化检查通过，验收矩阵有结果记录，且一份真实结构台账能够驱动三角色全链路和看板更新时，本轮需求才视为完成。
